# Mosque alpha decisions

## 2026-09-02 — One customer-outcome track owns alpha readiness

`mosque_alpha_20260902` is the only customer-alpha integration gate. The broad
private-beta track remains a platform program, because requiring builder,
governance, Bazaar, finance, federation, relays, and external MCP in one release
would make the alpha unbounded.

## 2026-09-02 — Hosted publication precedes custom domains

A stable Taawun-controlled `/s/{slug}` URL is mandatory. Custom domains are an
optional adapter and must use real public DNS and browser-trusted TLS if exposed.
This removes external DNS from time-to-first-value without weakening domain proof.

## 2026-09-02 — Deterministic guidance is the reliability floor

The AI proposal loop is valuable and should be feature-flagged into alpha when
its safety gates pass, but a live provider is not a release dependency. The same
typed draft, validation, and explicit confirmation boundaries apply with or
without AI.

## 2026-09-02 — Registration is explicit central custody

Event responses are server-owned transactional records, separate from signed
artifacts and local-first primitives. Product copy must state custody, purpose,
access, retention, export, and deletion. Sensitive-question categories are out.

## 2026-09-02 — Preserve substrate, simplify presentation

Finance, Bazaar, Shura, federation, relay, MCP, and trust details are hidden from
the default mosque journey rather than deleted. Advanced and development users
may retain access without making those concepts prerequisites for first value.

## 2026-09-02 — SQLite remains for the invited alpha

One Railway instance with SQLite is acceptable only with explicit single-instance
limits, consistent off-platform backup, and a successful restore drill. Database
migration is not a substitute for closing the product and operational gaps.
